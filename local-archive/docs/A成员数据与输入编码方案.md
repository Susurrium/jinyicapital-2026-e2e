# A 成员数据与输入编码方案

适用任务：进益资本杯 2026 端到端赛道。A 负责数据适配、时间窗口、标签构建、预处理和输入编码；B 负责时序主干、汇总、预测头和训练；C 负责目标函数、评价和平台提交。日期：2026 年 10 月 11 日，赛程均为北京时间。

**主线采用 Qlib ALSTMModel 的完整结构参照：原始数据与观测掩码 → Linear + Tanh 输入编码 → 两层 GRU → 时间注意力与最后状态 → 线性收益预测。**同时保留 Qlib GRU 简单参照和 DeepLOB 盘口结构参照。A 的分组 MLP 复用 Qlib Net 的完整前馈模块，分钟分块复用 PatchTST 的线性 patch 投影形式；两项研究均需要与对应参照进行受控比较。

模型结构参照、数据处理参照和本比赛必要适配分别记录。成熟项目的成绩不等于本比赛成绩；正式标签、采样、授权日期和平台限制以[比赛规则与流程](E:/PtoP/docs/比赛规则与流程.md)及官方材料为准。开发采用的结构和超参数是可追溯起点，最终候选通过本比赛授权数据的时间样本外验证确定。

本地实施状态见[真实数据验收与预处理检查](本地1分钟数据验收与预处理检查.md)。1 分钟全包已审计，8,084 个未知负委托笔数仍需来源说明或修正。七日 N0/N1 数值检查支持首轮联合训练优先检查 N1；正式拟合范围、采样集合及标签支持区间明确后再生成正式冻结状态。

## 4 字段与数据合同

存储字段顺序固定如下。此表用于数据注册，模型分组见第 9 节。

| 字段类别 | 固定顺序 | 数量 |
| --- | --- | ---: |
| OHLC | open, high, low, close | 4 |
| 成交 | volume, amount, deal_number | 3 |
| 盘口价格 | bid_price1, ask_price1, bid_price2, ask_price2, bid_price3, ask_price3 | 6 |
| 盘口数量 | bid_volume1, ask_volume1, bid_volume2, ask_volume2, bid_volume3, ask_volume3 | 6 |
| 委托笔数 | bid_num_orders1, ask_num_orders1, bid_num_orders2, ask_num_orders2, bid_num_orders3, ask_num_orders3 | 6 |

date、instrument_id 用于索引，instrument 用于输出映射。adjust_factor 保留为待核对的复权元数据。默认使用原始日内价格；未来 VWAP 和风险暴露不进入默认输入。人工收益率、价差、不平衡率、均线、滚动波动率等不加入特征表。

两端适配按以下顺序执行：

1. 核对来源、授权范围、schema 和时间范围，读取所需列。
2. 本地 OHLC 的 -1、云端 OHLC 的 NaN 按官方合同置为缺失；盘口价格 0 表示缺失报价，生成 observed。
3. 价格与 amount 转为 float64 后，本地除以 100，云端保持元单位。成交量、盘口数量和笔数不跟随缩放。
4. 核对唯一键、时间语义及股票映射，形成规范行。
5. 预处理只作用于有效数值；缺失位置在变换后填零。转换为 float32 后再检查有限性。

真实零成交量与缺失量分别处理。对应盘口价格缺失时，数量和笔数按各自合同判定，不能推测其缺失状态。未知负数量、冲突重复记录、无法映射的 ID 和未知单位须定位并阻断依赖操作；完全相同的重复行可以在规范层去重并记录数量，原始文件不改写。

本地整数化可能产生量化误差。单位转换一致性使用同一合成数值检查；来源量化一致性使用官方取整规则及授权重叠样本检查。未知取整方法时不向云端追加猜测性 round。

## 5 时间索引和缺失状态

先由正式采样时点与历史股票池生成应预测集合，再连接行情。样本键为 (decision_time, instrument_id)，同一时点共用 decision_id，另存稳定 sample_id。不能从“当前存在行情的股票”反推覆盖率分母。

每个输入记录满足 bar_end≤decision_time，且当时已经可得。官方只提供 Bar 结束时间时，需核对其可见性及历史修订口径。集合竞价、午休、尾盘、节假日和输出区间端点使用授权日历与模板；文件中存在 09:25 不代表它是合法输出时点。

默认窗口为当天最近至多 120 个已结束交易分钟，按旧到新排列；午休没有槽位，真实交易分钟缺记录仍保留。历史不足在左侧填充。使用这个配置前，必须确认每个正式采样时点已有可用的当天历史；否则需先解决授权历史和复权口径，启用跨日窗口并重新验收覆盖。

预测不跨夜与输入是否读取前日是两个独立条件。跨日窗口只在复权、历史缓冲及可见性明确后加入实验，目标仍满足官方非隔夜要求。不同窗口候选使用相同决策样本集合。

| 对象 | 形状 | 含义 |
| --- | --- | --- |
| observed | bool [B,L,25] | 具体字段有效且当时可得 |
| step_valid | bool [B,L] | 对应真实历史时间槽，独立于该股票有没有记录 |
| predictable | bool [B] | 整个窗口在当前模型实际使用的字段中至少有一个有效原始观测 |
| target_valid | bool [B] | 标签完整合法，仅训练和评价使用 |

observed=True 必须对应 step_valid=True。结构填充为 step_valid=False；真实缺失分钟为 step_valid=True、observed 全 False；真实零值的 observed=True。

全空窗口在模型调用前分流并记录原因，不用固定分数补齐。字段子集模型按所用字段重新计算 predictable，不能因未使用的字段有值就生成预测。部分缺失样本保留 mask，不添加未经验证的最低有效比例筛选。C 按完整应预测集合逐时点审计：缺失率不得超过 40%，且任何应输出时点不能整体缺失。停牌和零成交是否计入分母仍以官方合同为准。

## 6 预处理参照和选择规则

### 6.1 N0 固定稳健标准化

直接使用锁定版本的 Qlib RobustZScoreNorm，fields_group=feature、clip_outlier=False。Qlib 的[高频配置](https://github.com/microsoft/qlib/blob/54355232463878d2eebb91fe0ee5fa7fa1f5976c/examples/highfreq/workflow_config_High_Freq_Tree_Alpha158.yaml)包含这一处理组合；其 Alpha158 特征和目标不进入本比赛。

按字段使用本折合法训练原始行拟合：

\[
c_f=\operatorname{median}(x_f),\qquad
s_f=1.4826\bigl(\operatorname{median}|x_f-c_f|+\epsilon\bigr),\qquad
\tilde x_f=(x_f-c_f)/s_f.
\]

这里严格沿用该版本处理器的计算顺序，EPS=1e-12。统计量只使用有效观测。拟合集合为训练决策窗口引用的授权原始行并集，限制在拟合日期内并按键去重；重叠窗口不会重复计权，也不按标签数值或有效性筛选统计记录。

使用不裁剪的配置，是为了在原始字段上保留线性尺度变换后的幅度信息；它是现成高频配置的参照选择，不保证适合全部字段。正式选用前必须执行第 6.4 节的尺度检查。

### 6.2 N1 固定均值方差标准化

比较对象使用 Qlib ZScoreNorm，保持同一拟合记录和冻结规则。该实现采用逐字段 nanmean、nanstd；标准差为零的列把 mean_train 设为 0、std_train 设为 1，因此原值保持不变。不能把该语义写成其他库的“常量列统一变为零”。

N0 与 N1 均使用同一 DataHandlerLP/Processor 接口与状态保存机制，不另外编写统计算法。[Qlib 处理器源码](https://github.com/microsoft/qlib/blob/54355232463878d2eebb91fe0ee5fa7fa1f5976c/qlib/data/dataset/processor.py)

### 6.3 N2 共享价格尺度对照

Qlib HighFreqNorm 将多个价格列放入同一价格组拟合统计量。基于这一具体做法，增加一个小范围对照：十个原始价格字段共同使用一个训练期中心和正尺度，其他十五个字段保持所选固定处理器的逐字段状态。

十个价格字段包括 OHLC 与前三档买卖价格。统计集合取这些字段的有效训练观测并集，缺失不计入；中心和尺度采用与 N0 或 N1 相同的公式，只改变价格组的统计轴。所有价格以相同仿射变换处理，保留字段间大小顺序及差值的比例关系。该候选不引入新金融字段。

这是对[高频处理器](https://github.com/microsoft/qlib/blob/54355232463878d2eebb91fe0ee5fa7fa1f5976c/examples/highfreq/highfreq_processor.py)的限定适配：原示例还包含前置价格表达式、成交量变换及其专用输出组织。N2 只检验共享价格尺度的效果，不宣称重现原示例。

### 6.4 拟合检查和冻结

每个候选记录有效数量、中心、尺度、零值比例、分位数、极值及变换后的有限性，按字段、股票价格量级和日内时段检查。

- 全训练区间无有效观测、单位未明确或字段缺失：数据合同失败，停止相关操作。
- N0 的原始 MAD 为零、依赖 EPS 才有尺度：标记为退化，N0 不具备直接冻结资格。N1 按预登记流程独立评价；不在推理时自动切换算法。
- N1 的零方差列：保留官方处理器语义，并记录验证期变化；不能永久强制该列为零。
- 变换后出现非有限数值：定位来源、精度和处理状态，修复后重测。
- 即使数值有限，也要检查 Tanh 输入是否大范围进入接近 ±1 的输出区域，以及微小价格变化是否仍可分辨。不能仅凭“没有 NaN”认定尺度合适。

拟合按原始唯一行进行。Qlib 处理器没有被假定具有 partial_fit；数据规模较大时可逐列读取训练记录、逐列调用同一个官方处理器，利用其逐字段独立性合并状态，须与一次性拟合的短区间结果做等价测试。共享价格组按一个统计组处理，预先测量峰值内存。

先以主结构参照固定网络和训练条件比较 N0/N1，通过尺度检查后再比较 N2。最终选定的处理器类型、轴、参数、字段顺序和拟合范围全部冻结。推理只有 transform，不调用 fit，也不跨推理调用更新统计量。

DeepLOB 的 LSE 实验使用每只股票此前五天的数据标准化当日，说明时间变化值得检查；该原文不足以确定本比赛的全部统计轴和许可语义。当前正式候选使用可审计的训练期固定状态；任何依赖评测期历史重新计算统计量的实验都需先明确规则与计算合同。

## 7 Qlib 完整结构参照

### 7.1 R0 GRU 简单参照

复用 GRUModel 的两层 GRU、隐藏维度 64、dropout=0 和 Linear(64,1)。每分钟输入为：

\[
u_t=[\tilde x_t,\operatorname{float}(observed_t)]\in\mathbb R^{50}.
\]

A 的参照 encoder 直接返回 u 和 step_valid，D=50；B 的 GRU 使用最后有效状态输出分数。改变输入维度属于比赛字段适配，循环层和输出头保持原结构。[源码](https://github.com/microsoft/qlib/blob/54355232463878d2eebb91fe0ee5fa7fa1f5976c/qlib/contrib/model/pytorch_gru.py)

### 7.2 R1 ALSTM 主结构参照

复用 ALSTMModel，明确 rnn_type=GRU、hidden_size=64、num_layers=2、dropout=0。源文件的命名不决定循环单元类型，应按实际配置构建。

| 模块 | 结构 | 责任 |
| --- | --- | --- |
| 输入编码 | Linear(50,64) → Tanh | A |
| 时序主干 | 两层 GRU，输入与隐藏维度均 64 | B |
| 注意力打分 | Linear(64,32) → Dropout(0) → Tanh → Linear(32,1,bias=False) | B |
| 时间汇总 | 对有效时间槽做 Softmax，得到 GRU 状态的加权和 | B |
| 输出头 | 最后有效状态与加权状态拼接为 128 维 → Linear(128,1) | B |

Tanh、注意力形式和输出头作为完整参照保留；不为了统一全模型激活名称而替换其中某一层。参数初始化沿用锁定源码及锁定 PyTorch 版本的构造行为，不增加独立初始化覆盖。[源码](https://github.com/microsoft/qlib/blob/54355232463878d2eebb91fe0ee5fa7fa1f5976c/qlib/contrib/model/pytorch_alstm.py)、[官方配置](https://github.com/microsoft/qlib/blob/54355232463878d2eebb91fe0ee5fa7fa1f5976c/examples/benchmarks/ALSTM/workflow_config_alstm_Alpha360.yaml)

### 7.3 两个参照共同需要的适配

1. 将本比赛原始字段及 mask 组织为 [B,L,50]，不调用 Alpha360 的特征或标签构造。
2. Qlib 原模型将扁平数组解释为“字段、时间”顺序。等价测试中使用同一顺序转换，不能直接把 [B,L,F] 随意 flatten。
3. 左侧结构填充先转换为有效前缀和右侧填充，再使用 PyTorch pack_padded_sequence。内部真实缺失分钟保留。
4. ALSTM 注意力在 Softmax 前把 padding 的 logit 置为负无穷；至少有一个有效时间槽。源 att_net 最后的 Softmax 只执行一次。
5. 原始完整窗口不包含 padding 时，适配模型与相同权重的源码模型输出及梯度在声明容差内一致。
6. 目标替换为正式 30 分钟 VWAP 收益；完整推理不读取标签表。
7. A/B 的职责拆分只改变模块组织，不能改变计算图。最终训练必须联合更新 encoder、GRU、注意力和输出头。

R0/R1 是针对本赛道的结构参照，未在 Qlib 原始数据集复现其公开 benchmark 数值，因此不使用“已复现 Qlib 成绩”的表述。

按上述层次计算，R0 完整模型有 47,297 个可训练参数，R1 有 55,425 个；R1 的输入 encoder 占 3,264 个。实现时逐模块核对参数数量及权重名称，拆分 A/B 模块不能重复保留一个额外输入投影。

## 8 DeepLOB 盘口结构参照

DeepLOB 与原始盘口输入更相近，保留其“盘口卷积 → 多尺度 Inception → LSTM”完整顺序，不能只以逐档 MLP 代替该结构后引用原模型的整体效果。

### 8.1 输入与必要差异

每档按 ask_price、ask_volume、bid_price、bid_volume 排列，前三档共 12 个字段。A 同时重排 observed，构造数值与观测标志两个输入通道，[B,2,T,12]。数据使用与 Qlib 参照相同的规范层、拟合记录和时间样本。

相对作者的十档、事件序列、三分类任务，本比赛需要以下明确适配：

- 档位宽度由 40 变为 12，最后的档位汇聚卷积宽度由 10 变为 3。
- 分钟频率代替事件频率，历史长度独立记录；不能把 100 个事件解释为 100 分钟。
- 增加观测通道以保留缺失语义。
- 输出改为一个线性收益分数，由 C 的同一回归目标训练。
- 推理使用固定权重和确定的 eval 行为；训练 Dropout 与推理严格区分。

### 8.2 保留的层次

层次规格参考论文及已核对的[作者 TensorFlow 2 示例](https://github.com/zcakhaa/DeepLOB-Deep-Convolutional-Neural-Networks-for-Limit-Order-Books/blob/ff14d7c2fd38bdfc143389786993d0f0236d4eb8/jupyter_tensorflow/run_train_tensorflow-version2.ipynb)；论文图示与不同示例的通道数、归一化、Dropout 有版本差异，实验记录必须指明采用的规格，不能混合后称为原版。

| 模块 | 本赛道结构参照 |
| --- | --- |
| 盘口卷积一 | 32 通道，核 (1,2)、步长 (1,2)；随后两个 32 通道 (4,1) 时间卷积 |
| 盘口卷积二 | 32 通道，核 (1,2)、步长 (1,2)；随后两个 32 通道 (4,1) 时间卷积 |
| 档位汇聚 | 32 通道，核 (1,3)；随后两个 32 通道 (4,1) 时间卷积 |
| Inception 分支一 | 64 通道 (1,1)，再接 64 通道 (3,1) |
| Inception 分支二 | 64 通道 (1,1)，再接 64 通道 (5,1) |
| Inception 分支三 | (3,1) 最大池化、步长 1，再接 64 通道 (1,1) |
| token | 三分支沿通道拼接，得到 [B,T,192] |
| 时序与输出 | LSTM 隐藏维度 64，最后有效状态接 Linear(64,1) |

各卷积后使用 LeakyReLU(0.01)。时间卷积使用与该规格一致的 same padding，保留时间长度；核长 4 时，在时间前侧补 1、后侧补 2 个零。空间卷积采用 valid，宽度按 12→6→3→1 减少。最大池化保留时间长度，边界处理与源算子一致，以包含负值的样例核对，不能任意用零值抬高边界最大值。训练采用沿时间共享通道 mask 的 Dropout(0.2)，推理关闭。该配置依据作者 TensorFlow 结构，不加入其他示例的 BatchNorm 或 Tanh。

本赛道的 PyTorch 实现明确记录框架转换：卷积和线性权重采用 Glorot/Xavier uniform，bias 为零；LSTM 输入权重采用相同初始化，循环权重采用 orthogonal，两个 bias 向量之和在遗忘门部分为 1、其余为零。这对应所参考 Keras 层的初始化约定，不能直接以 PyTorch 默认 LSTM 初始化代替。LSTM 使用 Tanh 状态激活和 Sigmoid 门函数。跨框架比较需要按门顺序、权重转置及合计 bias 映射；不要求不同框架以同一随机种子生成相同权重。[Keras LSTM](https://keras.io/api/layers/recurrent_layers/lstm/)、[Conv2D](https://keras.io/api/layers/convolution_layers/convolution2d/)

每个决策截面的真实时间槽数量相同，可以在 CNN 前去掉共同的左侧结构填充；不同长度的截面分组运行，再恢复原顺序。真实分钟中的字段缺失保留数值零及观测通道。这样不会让人为补齐的长前缀参与卷积编码。时间卷积只处理本次决策已可得的整个历史窗口。

A 负责卷积和 Inception 编码，B 负责 LSTM 与输出头。许可和依赖条件未明确前不复制作者仓库代码；按论文组织标准算子的实现也需记录来源、通道规格、padding 和全部适配。

### 8.3 必须使用同字段对照

增加 R1-Book：Qlib ALSTM 只接同样 12 个盘口字段及 12 个 observed。两者按该字段子集使用同一 predictable 和目标有效性规则，比较 DeepLOB 适配与 R1-Book，才能评价盘口架构差异；R1 的 25 字段结果另行报告，不能用字段数量差异解释架构优劣。各模型的正式覆盖仍按完整官方应预测集合检查，不能用比较样本子集替代覆盖分母。

盘口参照依然必须满足短历史、缺失、逐时点覆盖和资源限制。只在完整样本子集取得好结果，不能直接证明适合正式提交。

## 9 A 的分组 MLP 研究

### 9.1 统一编码参照

直接复用 Qlib Net(input_dim=50, output_dim=64, layers=(256,), act="LeakyReLU")：

Dropout(0.05) → Linear(50,256) → BatchNorm1d(256) → LeakyReLU(0.1) → Dropout(0.05) → Linear(256,64)。

保留其原始初始化：源码对各 Linear 权重使用 Kaiming normal，a=0.1；bias 和 BatchNorm 构造行为以锁定版本为准。输出不增加 LayerNorm 或另一个融合层。[Net 源码](https://github.com/microsoft/qlib/blob/54355232463878d2eebb91fe0ee5fa7fa1f5976c/qlib/contrib/model/pytorch_nn.py)

这项实验只替换 R1 的输入编码，其后的 GRU、注意力、头和 C 的目标保持一致。它检验一个完整成熟 MLP 模块作为 token encoder 是否带来增益，不将原 Qlib MLP 的整体表现直接移用于该组合。

### 9.2 分组与配对控制

分组任务使用三组：OHLC 4 字段、成交 3 字段、完整三档盘口 18 字段。盘口的价格、数量和笔数在同一分支内共同输入，保留它们早期交互的机会。

每组均实例化原版 Net，输入为该组数值及 mask，hidden=256、output_dim=64。三个输出按固定组顺序拼接成 192 维 token，B 的首层 GRU 输入维度随配置设为 192，其余结构保持一致。

配对控制使用统一 Net(input_dim=50, output_dim=192, layers=(256,))，接同样输入维度的 B 模型。两者 token 宽度相同，参数量接近，避免把输出宽度变化误作分组收益：

| 编码器 | 可训练参数量 |
| --- | ---: |
| ALSTM 原输入投影 50→64 | 3,264 |
| 统一 Net，50→256→64 | 30,016 |
| 统一 Net，50→256→192 | 62,912 |
| 三组 Net，各输出 64，拼接 192 | 64,448 |

数字按锁定模块层次计算，不包含 B；实现时再用程序核对。三组划分属于团队研究假设，成熟来源支持 Net 模块，不能替分组效果作结论。

### 9.3 BatchNorm 与 mask

只收集 step_valid=True 的分钟行进入 Net，保持共同的扁平行顺序；输出后散回对应时间槽。结构填充不进入 BatchNorm，真实缺失分钟仍以数值和 observed 表示。训练统计轴为当前训练 batch 的有效分钟行，不能把验证数据混入统计。

推理使用 eval，加载全部 running_mean、running_var 和 num_batches_tracked。batch 重排、批次规模和分区改变后，恢复样本顺序的结果应在声明容差内一致。若有效行不足以进行训练期 BatchNorm，显式合并合法训练批次或报错，不能临时改成 eval 来假装完成训练。

先评价完整 Net 模块；只有其适配通过后，才单独比较负斜率、激活或归一化位置。每次改动记录对应初始化、BN 状态和训练预算，不混合归因。

## 10 分钟分块研究

使用一个直接的联合线性投影，参考 PatchTST 附录“仅使用 patch、混合通道”的消融形式。每分钟拼接 25 个值、25 个 observed 和一个 step_valid，得到 51 维输入。

对最近 P 个交易分钟，按“字段优先、字段内时间从旧到新”的 51×P 顺序展平，第 51 个字段为 step_valid，经 Linear(51P,64) 得到 token。P=1、S=1 与 P=5、S=5 使用相同的数据和 B 模型；L=120、P=S=5 时最多 24 个 token。该分支不增加分组瓶颈或额外融合层。

片段按决策端向历史编号，左侧不足保留数值、observed 和 step_valid；patch_valid 为块内 step_valid 的 any。纯结构填充块排除，真实缺失分钟保留位置。记录每块起止真实时间，不生成午休虚构分钟。

这是一项采用作者分块投影形式的组件实验，后续仍使用 R1 的 GRU 和注意力；它不具备完整 PatchTST 的通道独立 Transformer 和同变量预测头，实验名称采用“联合线性 patch + GRU”。P=1 控制用于区分线性投影形式与分块效果。[论文附录](https://arxiv.org/html/2211.14730)、[作者投影实现](https://github.com/yuqinie98/PatchTST/blob/204c21efe0b39603ad6e2ca640ef5896646ab1a9/PatchTST_supervised/layers/PatchTST_backbone.py)

投影初始化使用 PyTorch Linear 的锁定版本默认行为，所有 P 候选记录初始状态。P=5 时投影参数量为 16,384；不同 P 的参数量和计算量分别报告，不能只凭 token 数估计总体加速。

B 的 Transformer 研究在最终固定 A 输入后开展，并保持输出任务和 mask 正确。任何来源代码的 padding 参数都需检查实际调用链，不能从构造函数参数名推定已支持动态缺失。

### 11.1 规范分区接入

### 11.2 使用 TSDataSampler

默认按日实例化 TSDataSampler，step_len=L、fillna_type="none"。先用官方分钟网格和当日相关股票补齐索引，即使整个时点没有原始记录也保留行；再用 flt_data 选择正式决策端点。

该组件负责数组索引与历史取窗；适配层负责：

- 日界线与午休网格；
- observed、step_valid 的构造；
- 正式股票池和应预测索引；

TSDataSampler 会修改传入 DataFrame 的列以释放内存，必须传入明确归它所有的分区对象或独立副本，不能破坏上游复用对象。对构造行为、端点过滤、缺失位置和输出顺序进行集成测试。[采样器源码](https://github.com/microsoft/qlib/blob/54355232463878d2eebb91fe0ee5fa7fa1f5976c/qlib/data/dataset/__init__.py)

### 11.3 缓存和资源

只缓存规范数值、原始观测掩码、索引及冻结预处理结果，不缓存训练中的学习后 token。缓存键包含数据分区、字段、时间合同和预处理状态指纹。

不展开保存全部重叠窗口，不在每个 epoch 重复解压。训练分区读取与 batch 预取采用 PyTorch DataLoader；Windows worker 入口和随机状态按官方方式管理。缺少必要依赖直接报错，不在运行时下载。

以 1,000 只股票、240 个分钟、25 个 float32 字段估算，一日数值约 24 MB、bool observed 约 6 MB；一个 L=120 截面的数值约 12 MB。构造 50 维浮点模型输入约 24 MB，64 维分钟 token 约 30.72 MB，192 维约 92.16 MB。这些数值不包含 DataFrame、索引、复制、模型激活与反向传播。

完整推理预算包含读取、规范化、建窗、模型、连接输出和校验。当前按 3 小时验收，内部目标 2.5 小时。先测授权短区间和高数据量区间，再测平台完整区间；不能用理论张量大小代替实测内存或耗时。

## 13 训练参照和实验顺序

### 13.1 训练配置

R0/R1 使用 Qlib GRU/ALSTM 配置作为训练起点：Adam、学习率 1e-3、MSE、最多 200 epochs、验证 loss 连续 20 epochs 不改善则早停、按值裁剪梯度至 ±3。这里保留可追溯初值，实际完整训练耗时由数据规模测量确定。

数据改为本比赛输入、正式目标和时间切分。batch 默认按完整决策截面组织，以便 C 的排序目标使用；MSE 可以按样本数准确加权分块。不能直接套用源码训练循环中删缺失整行、丢弃尾批次等行为。验证和推理覆盖全部应处理样本。

C 的 Huber 与排序研究保持完整职责：在参照 MSE 上单独改变目标，Huber 的 delta 按训练标签量纲确定并报告落入二次区间的比例，不机械套用与收益尺度无关的参数。比较 A 的编码器时固定 C 的目标、B 的网络及训练规则。

DeepLOB 参照与 Qlib 参照先使用共同的回归训练协议，再按相同预算比较学习率 {1e-3,3e-4,1e-4}；区分固定协议结果与调参后完整配置结果。没有复现原分类目标、原数据和原训练流程时，不声称复现原论文指标。

### 13.2 实验卡

| 顺序 | 实验 | 固定条件与要回答的问题 |

主参照始终保留。研究分支表现接近或不稳定时，不因模型名称或参数更多而替换参照。分组、patch 或某个激活没有增益，也构成有效研究结果，应完整保留证据。

任何真实训练前都先完成预处理质量检查。N0 退化或未通过有限性检查时不执行该候选的训练，由预登记 N1 分支继续评价；这一选择写入配置和实验记录，不能在同一训练或推理过程中自动更换处理器。

对进入最终比较的候选，两个开发折至少使用三个相同预登记种子，例如 17、43、101。记录每次结果，不能只选最佳种子。候选使用相同样本量、训练更新预算和调参预算，同时单独报告实际耗时。

### 13.3 诊断与选择

A 记录输入尺度、mask 比例、激活前后分布、Tanh 饱和程度、BN 运行状态及梯度有限性；C 报告 IC、IC_IR、夏普、压力场景和换手五类指标，以及逐日、逐时段和缺失程度分组结果。

模型保留依据为：规则和覆盖合格、源实现适配正确、加载可复现、资源达标、样本外效果稳定。训练 loss 或某个诊断数值不能单独决定最终候选。对相同日期的差异按整日或连续多日区块重采样，区块长度预先规定，不将每只股票视为独立统计证据。

平台综合分数使用全体有效提交的百分位，队内加权指标不能冒充官方分数。记录每次提交及其选择依据；官方候选数量确定后，由 C 按完整证据组织冻结。

## 14 A B C 接口与模型包

外部接口继续使用：

~~~python
tokens, token_valid = encoder(x, observed, step_valid)
scores = model(x, observed, step_valid)
loss = objective(scores, target, decision_id)
~~~

x 为 float32 [B,L,25]，observed 为 bool [B,L,25]，step_valid 为 bool [B,L]。tokens 为 [B,N,D]，N、D 由 encoder 配置确定：R0 的 D=50，R1 的 D=64，分组配对与 DeepLOB 的 D=192，patch 的 D=64。各方不能硬编码所有模型均为 D=64。

样本元数据包含 sample_id、decision_id、instrument_id、decision_time；训练/评价另有 target、target_valid、target_end。外部 mask 一律 True=有效，调用反向语义的库参数时显式转换。排序、packing、按长度分组和分区推理后恢复 sample_id 顺序。

B 的模型包包含：

- 模型类型、输入字段及顺序、所有模块配置与完整权重。
- Qlib/PyTorch 等依赖版本、来源 commit、必要许可。
- encoder 类型、输入拼接和分组顺序、激活、归一化、Dropout、初始化及 BN buffers。
- 预处理器类型、统计轴、数值状态、拟合范围和样本数量。
- 正式采样、股票池、窗口和标签合同版本。
- 配置、随机种子、训练范围、实际运行记录及 C 的选择记录。

恢复时验证 schema、状态版本及模块形状；缺少必要参数立即报错。训练恢复另外包含优化器、调度器和随机状态。正式推理不重新初始化、不重新拟合、不更新 BN 统计。

C 的唯一 Notebook 调用同一处理器及模型加载入口，提供 main(datasources,start_date,end_date)，返回恰好 date、instrument、score 三列。行情数据源动态取得；最终输出仅限正式区间，全部分数有限且键唯一。
