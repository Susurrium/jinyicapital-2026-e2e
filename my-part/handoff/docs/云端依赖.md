# 云端依赖与运行环境

交接包当前支持 Python 3.12，首轮使用 R1、N1、120 分钟窗口。已运行的开发环境是 Windows x64、Python 3.12.10、PyTorch 2.8.0 CPU。Linux、CUDA、DAI 服务连接及平台隔离运行环境尚未运行验证。B 负责在实际训练和推理环境安装一致的依赖，并记录最终使用的环境。

本说明中的命令均在解压后的交接包根目录执行。Shell 中的 `python` 必须与实际执行训练的 Notebook 内核使用同一个解释器；可在 Notebook 查看 `sys.executable` 并将命令中的 `python` 替换成该绝对路径。

## 固定版本及平台依赖

| 项目 | 版本或来源 | 用途 |
| --- | --- | --- |
| Python | `>=3.12,<3.13`，开发环境为 `3.12.10` | 当前包的支持范围 |
| NumPy | `2.2.6` | 数值和数组 |
| pandas | `2.2.3` | DataFrame、时间索引 |
| PyArrow | `20.0.0` | 数据文件及 Qlib 依赖 |
| psutil | `7.2.2` | 资源记录 |
| PyTorch | `2.8.0`，CPU/CUDA 构建由实际平台决定 | 模型和联合训练 |
| Qlib / 安装包名 `pyqlib` | commit `54355232463878d2eebb91fe0ee5fa7fa1f5976c`；分发版本 `0.0.0+git.54355232463878d2eebb91fe0ee5fa7fa1f5976c` | `TSDataSampler`、预处理和原始模型组件 |
| pytest | `8.4.2` | 运行交接测试时需要 |
| `dai` | 比赛云端平台提供的客户端及访问权限 | `dai.query` 读取官方表 |
| `bigmodule` | 比赛云端平台提供的模块 | 官方预测模板中的 `M` 接口 |

`requirements-core.txt` 固定直接数值依赖；`requirements-test.txt` 额外固定 pytest。PyTorch 单独选择构建，Qlib 从包内官方固定提交源码构建。完整传递依赖在目标环境准备后记录，并固定用于训练和推理；本包没有宣称已生成 Linux/CUDA 的完整环境锁定结果。

Qlib 的传递依赖由该提交的 `pyproject.toml` 声明，包括 pandas、NumPy、MLflow、LightGBM 等。安装 Qlib 时正常解析这些依赖；最终通过 `pip check`，并保留环境记录和同一批安装文件。不要只复制 `qlib/` Python 目录，Qlib 还包含需要编译的扩展。

`dai`、`bigmodule` 使用平台预装模块或平台官方提供的安装文件。不能依据 PyPI 同名包猜测安装来源。代码仓库未携带平台凭据，源代码打包完成也不代表已取得官方数据表的访问权限。

## 安装前核对解释器和设备

在平台已配置的 Notebook 内执行：

```python
import sys
import torch

print(sys.executable)
print(sys.version)
print(torch.__version__)
print(torch.version.cuda)
print(torch.cuda.is_available())
```

同时核对平台提供的 GPU 型号、驱动、Python 版本及提交环境可用的依赖。现有 PyTorch 构建符合要求时沿用它。需要安装 CUDA 构建时，依据平台驱动兼容性选定下载索引；不要为了完成依赖安装把已提供的 GPU 构建替换为 CPU 构建。

PyTorch 官方为 2.8.0 列出了 CUDA 12.6、12.8、12.9 和 CPU 索引。项目只使用 `torch`，不要求 `torchvision`、`torchaudio`。[PyTorch 2.8.0 官方安装命令](https://pytorch.org/get-started/previous-versions/#v280)

| 已确定的运行环境 | `TORCH_INDEX_URL` |
| --- | --- |
| CUDA 12.6 构建 | `https://download.pytorch.org/whl/cu126` |
| CUDA 12.8 构建 | `https://download.pytorch.org/whl/cu128` |
| CUDA 12.9 构建 | `https://download.pytorch.org/whl/cu129` |
| 明确使用 CPU | `https://download.pytorch.org/whl/cpu` |

下列步骤适用于已选定解释器且允许在开发阶段联网安装的 Linux 平台。临时文件和缓存统一写入解压目录下的 `work/`。

```bash
mkdir -p work/python-temp work/pip-cache work/wheelhouse
export TMPDIR="$PWD/work/python-temp"
export TMP="$TMPDIR"
export TEMP="$TMPDIR"
export PIP_CACHE_DIR="$PWD/work/pip-cache"
python -m pip install -r requirements-test.txt
```

若确实需要安装 PyTorch，先将 `TORCH_INDEX_URL` 设为上表中已确认的一项，再执行：

```bash
python -m pip install torch==2.8.0 --index-url "${TORCH_INDEX_URL:?请先根据平台选择 PyTorch 索引}"
```

## 构建固定提交 Qlib 并安装 PtoP

包内文件 `third_party/qlib-54355232463878d2eebb91fe0ee5fa7fa1f5976c.zip` 包含固定提交的完整 `qlib/` 源码及构建文件，每个文件均与上游原文一致。Linux 需要 C++ 编译器、匹配当前 Python 的开发头文件，以及平台允许的系统运行库；由平台环境提供这些前置条件。本地开发用的 Windows wheel 无法在 Linux 使用。

以下设置保留指定提交的分发版本；构建依赖先安装，构建时关闭隔离以明确使用已固定的 NumPy。固定提交所需的构建依赖来自其官方 `pyproject.toml`：[Qlib 固定提交构建配置](https://github.com/microsoft/qlib/blob/54355232463878d2eebb91fe0ee5fa7fa1f5976c/pyproject.toml)。

```bash
export SETUPTOOLS_SCM_PRETEND_VERSION_FOR_PYQLIB=0.0.0+git.54355232463878d2eebb91fe0ee5fa7fa1f5976c
python -m pip install "setuptools>=75" setuptools-scm cython wheel
python -m pip wheel --no-build-isolation --wheel-dir work/wheelhouse -c requirements-core.txt third_party/qlib-54355232463878d2eebb91fe0ee5fa7fa1f5976c.zip
python -m pip install --no-index --find-links work/wheelhouse -c requirements-core.txt pyqlib==0.0.0+git.54355232463878d2eebb91fe0ee5fa7fa1f5976c
python -m pip install --no-deps --no-build-isolation .
python -m pip check
```

`--no-deps` 仅用于最后安装本项目自身：此前已经安装核心依赖、选定的 PyTorch 及完整 Qlib 依赖，以免再次根据项目元数据访问 GitHub 或重新选择 PyTorch 构建。任何一步失败，都应保留输出并处理对应环境问题。

安装完成后执行指定设备的环境检查。GPU 训练使用：

```bash
python scripts/prepare_environment.py --device cuda --require-platform --output work/cloud-environment.json
```

明确使用 CPU 时将 `--device cuda` 改为 `--device cpu`。`--require-platform` 会导入官方模板需要的 `dai`、`bigmodule`、`structlog`；在独立构建机上准备安装包时可省略它。脚本核对版本、导入 Qlib 并在指定设备执行基础张量计算，记录全部已安装分发版本；不读取行情、不查询标签、不启动训练。它不能代替 DAI 数据权限核对和 B/C 联合训练入口实现。

## 隔离环境的离线依赖准备

提交包附带 Qlib 源码；完整 Linux/CUDA wheelhouse 尚未构建。若正式运行环境禁止联网，需要 B 在与目标相同的操作系统、架构、Python 3.12、PyTorch 构建和兼容系统运行库环境中提前构建并测试 wheelhouse。Windows 已有安装文件不能作为 Linux 离线依赖包。

沿用上面已经成功构建 Qlib 的 `work/wheelhouse`，在该目标环境继续准备：

```bash
python -m pip wheel --wheel-dir work/wheelhouse -r requirements-test.txt
python -m pip wheel --wheel-dir work/wheelhouse torch==2.8.0 --index-url "${TORCH_INDEX_URL:?请先根据平台选择 PyTorch 索引}"
python -m pip wheel --no-deps --no-build-isolation --wheel-dir work/wheelhouse .
```

上述步骤将 Qlib、核心包、测试包、PyTorch 及它们的依赖构建或下载为 wheel；平台专用的 `dai`、`bigmodule` 仍以目标平台提供的环境为准。官方模板所需的 `structlog` 也须在训练、推理环境核对；当前核心包不自动安装它。保存 `work/cloud-environment.json` 和 wheelhouse，分别交给训练与推理环境。确认符合比赛对文件类型、体积和安装阶段的规则后再上传。

在目标隔离环境，解压到包根目录并设置前述 `TMPDIR`、`TMP`、`TEMP`、`PIP_CACHE_DIR` 后安装：

```bash
python -m pip install --no-index --find-links work/wheelhouse -r requirements-test.txt torch==2.8.0 pyqlib==0.0.0+git.54355232463878d2eebb91fe0ee5fa7fa1f5976c
python -m pip install --no-index --no-deps --find-links work/wheelhouse ptop==0.1.0
python -m pip check
python scripts/prepare_environment.py --device cuda --require-platform --output work/inference-environment.json
```

wheelhouse 必须仅包含这次确定的 PyTorch 构建及一致的依赖版本；更换构建时使用新的目录并重新准备。对平台专用模块的缺失，向平台确认正确环境或官方安装材料。

## 模型保存和推理的一致性

`save_bundle` 将 `torch`、`pyqlib`、`numpy`、`pandas`、`pyarrow` 的实际分发版本写入 `manifest.json`。`load_bundle` 要求这五项与推理环境完全一致；`2.8.0`、`2.8.0+cpu`、`2.8.0+cu126` 等记录会被视为不同版本。因此，训练前确定推理环境能安装同一批依赖；同一 CUDA wheel 可用于无 CUDA 计算的 CPU 推理时，也必须先确认该 wheel 在目标环境可正常导入运行。

B 负责保留依赖记录、训练和推理入口、模型 JSON 包及运行日志；C 负责给出标签和切分的合同版本。A 的 N1 预处理统计量需要在确定的云端训练数据上拟合并冻结，随模型包保存。平台注入的测试日期不能用于重新拟合预处理器。
